# OpenDVA — Open Dimensional Variation Analysis

A 3DCS-style three-dimensional tolerance / variation-analysis engine.
Clean-room implementation based on the design analysis in [`../doc/README.md`](../doc/README.md)
and the development plan in [`../doc/开发计划-多智能体协同.md`](../doc/开发计划-多智能体协同.md).

## Build

**Windows (MSVC, used for verification):**
```bat
:: from repo root
verify.bat
```
This calls `vcvars64.bat`, then configures + builds with the VS-bundled
CMake + Ninja into `build/` and runs the full test suite.

**Any platform (CMake ≥ 3.28, C++17):**
```sh
cmake -S src -B build -G Ninja -DOPENDVA_BUILD_TESTS=ON
cmake --build build
ctest --test-dir build --output-on-failure
```

## Run

```sh
# headless Monte Carlo on the built-in golden model
build/app/cli/opendva --runs 20000 --seed 12345 --threads 4 --out report.html

# starter desktop smoke: save XML, reopen, run Monte Carlo, export HTML
build/app/cli/opendva --starter-smoke --model-out starter.xml --runs 1000 --seed 12345 --threads 4 --out starter-report.html

# analyze a saved OpenDVA XML model and export HTML/CSV/Excel-XML/HST/HLM
build/app/cli/opendva --model-in starter.xml --runs 1000 --seed 12345 --threads 4 --out model-report.html --csv-out model-report.csv --excel-out model-report.xml --hst-out model-report.hst --hlm-out model-report.hlm

# run a simple batch queue; each line can be either:
#   # comment
#   model.xml
#   model.xml,runs,seed,threads  # optional inline comment
# Relative model paths are resolved from the batch-list file directory.
# Each item writes batch-N.html/csv/xml.xls/hst/hlm under batch-reports.
build/app/cli/opendva --batch-list batch-list.txt --batch-out-dir batch-reports --runs 1000 --seed 12345 --threads 4
```

## Options

| CMake option | Default | Effect |
|---|---|---|
| `OPENDVA_BUILD_TESTS` | ON | unit + contract tests |
| `OPENDVA_BUILD_UI` | ON | Qt6/Qt3D desktop UI |
| `OPENDVA_USE_OCCT` | OFF | OpenCASCADE geometry kernel (else stub) |
| `OPENDVA_WARNINGS_AS_ERRORS` | OFF | `/WX` or `-Werror` |

## Design invariants (the red lines)

1. Logic Tree node order == Move execution order == assembly sequence.
2. Fixed traversal order (tolerances → moves → measures, child→parent) ⇒
   same seed + same runs ⇒ bit-for-bit reproducible (enforced by a test).
3. Population sigma uses `/n`, not `/(n-1)`.
4. Modules talk **only** through `interfaces/`; no cross-module implementation
   includes.
5. The L1 engine runs fully headless (the CLI is the proof) for CI.
